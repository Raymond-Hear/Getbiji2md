# UI Notes

## Purpose

This document tracks frontend direction for the landing page and related product-facing pages.

## Current Direction

- The homepage should feel modern, calm, and product-oriented.
- The first screen should be visually strong but not text-heavy.
- Detailed explanation belongs below the fold.
- Privacy and FAQ should be accessible from the homepage by scrolling, not only by separate-page navigation.
- The tool page should not surface privacy/help links too prominently in the main working area.
- The site should show more real product imagery and less text-only explanation.

## Homepage Rules

### Hero

- Keep the hero concise.
- One clear headline.
- One short supporting paragraph.
- One primary action and one secondary action.
- Light supporting trust signals only.
- No process narration, no internal design explanation, no collaboration language.

### Mid-page Content

- Use this area to explain:
  - key product value
  - workflow
  - trust boundaries
- Keep cards short and scannable.
- Avoid turning every section into a wall of explanation.
- Whenever possible, pair explanation with real screenshots instead of text-only cards.
- The homepage should visually prove the product, not just describe it.

### Privacy Section

- Explain only what a normal user needs:
  - what is stored
  - what is not stored
  - what to pay attention to
- Keep the tone plain and reassuring.

### FAQ Section

- Keep only high-frequency questions.
- Prefer collapsible items for density control.
- Avoid repeating long explanations already covered elsewhere.

## Copy Guidance

- Write from the user's point of view.
- Do not describe redesign decisions inside the page.
- Do not mention that content was moved, merged, simplified, or rewritten.
- Avoid "meta copy" about the page itself.

## Visual Guidance

- Dark, cinematic hero is acceptable.
- Lower sections should breathe more and use lighter surfaces.
- Strong hierarchy:
  - bold headline
  - short supporting text
  - compact cards
- Prefer fewer, better sections over many similar blocks.
- Real screenshots should drive the product story in lower sections.
- Generated imagery, if used, should stay atmospheric and should not replace real UI.

## Things to Watch

- Hero text density
- Mobile header crowding
- Card text length
- Repetition between sections
- Whether the page feels like a product site instead of a design exercise
- Whether the page shows the actual tool enough
